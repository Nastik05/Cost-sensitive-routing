# Контроль отбора и выбора маршрутизатора

Протокол зафиксирован до вычисления нового follow-up. Он продолжает exploratory анализ ранее просмотренного BANKING77 test; не является пререгистрацией независимого исследования.

## Вопросы

1. Как меняются train/test ошибка и разброс при росте числа парных примеров?
2. Как влияет обогащение исходами при фиксированных экспертах и признаках? Восстанавливает ли коррекция весами качество естественного потока?
3. Каковы результат и потеря выбора метода по отдельному selector-dev относительно фиксированных правил?

## Фиксированные условия

- Две исходные пары из `data/manifest.json`: TF–IDF → BERT-tiny и TF–IDF → frozen MiniLM. Эксперты не переобучаются. Один датасет, общие эксперты: пары не независимые задачи.
- Пул router-fit: 2000; policy-dev: 1000; official test: 3080; clean sensitivity: 3072. Исходный кэш и его SHA проверяются.
- Числа обучающих извлечений: 200, 500, 1000; 30 повторений с seeds 0–29. Квоты: 10%, 20%, 40%; основная — 20%.
- Новый контролируемый отбор **с возвращением**, а не прежняя exponential-race выборка без возвращения. Natural — равновероятные извлечения из пула. Для rescue-rich множитель 4 у спасений, для harm-rich — 8 у вреда, для discordant-rich — 4 у обоих ненейтральных исходов.
- Если множитель строки равен aᵢ, вероятность извлечения pᵢ = aᵢ / Σaⱼ, корректирующий вес wᵢ = 1/(N pᵢ). Это известная вероятность каждого извлечения, не вероятность включения хотя бы раз. Усреднение взвешенной потери по числу извлечений несмещённо оценивает риск **конечного исходного пула** для фиксированной функции. Веса не нормализуются по реализации.
- Corrected/uncorrected используют одни строки, одинаковую невзвешенную стандартизацию и одинаковую сетку. Повторы не считаются новыми уникальными аннотациями; сохраняются число уникальных строк и эффективный размер по весам. Для отбора доступны исходы всего пула, поэтому экономия acquisition не заявляется.
- Методы direct (ridge) и events (две logistic-головы) — во всех составах, с весами и без. Weak-error и confidence — дополнительные natural baselines. Порядок tie-breaking фиксирован и общий внутри разбиения.
- Гиперпараметр: четыре прежних значения регуляризации; natural tuning-dev размера n/2 минимизирует gain MSE. На точном равенстве выбирается более сильная регуляризация. Обученный метод не меняется после просмотра test.
- Оставшиеся 500 policy-dev объектов (индексы 500–999 общей перестановки) — selector-dev; не пересекаются с tuning-dev. Выбор между confidence, weak-error, direct, events на natural fit по accuracy при данной квоте. На точном равенстве порядок предпочтения: confidence, direct, weak-error, events. Выбранный роутер не переобучается.

## Метрики и сохраняемые данные

Train, tuning-dev, selector-dev, official/clean test: accuracy, gain MSE, спасения, вред, точное число вызовов. Для confidence MSE не трактуется как калибровка gain. Отдельно: выбранная регуляризация, число уникальных fit-строк, ESS, fit IDs, dev IDs, fitted models, test scores, число параметров и время обучения. Train-кривые показывают natural sampling; ошибки enriched train и natural test нельзя трактовать как обычный generalization gap.

Selection regret: разница test accuracy лучшего из четырёх доступных fitted candidates и выбранного на selector-dev. Test oracle — только диагностический ориентир; не deployable метод и не основание выбора.

## Неопределённость

- Среднее и SD по 30 обучающим извлечениям условны на фиксированные пулы и экспертов; SD не доверительный интервал и не разброс по независимым датасетам.
- Заранее определённая follow-up семья из 14 контрастов, только n=1000, official test, квота 20%: corrected−uncorrected для 2 пар × 3 обогащения × 2 метода (12), selector−confidence для 2 пар (2).
- 2000 crossed paired bootstrap повторов: общий resampling test-строк и общий resampling 30 seeds. В каждом пакете top-k пересчитывается с учётом кратностей. Одна приближённая centered max-|t| поправка на все 14 контрастов. Обученные модели и выбор по dev условно фиксированы; вариация базовых экспертов и исходных пулов не моделируется. Перенос и эквивалентность не проверяются.
- Остальные разрезы, clean sensitivity и сравнения с natural — описательные; не выбирать постфактум новую статистическую семью по понравившимся результатам.

## Запуск

`python3 code/followup.py` — обучение и сохранение сырых результатов.

`python3 code/analyze_followup.py` — проверка метрик по scores, статистика, таблицы и рисунки без обучения. Результаты в `code/results/followup/`, публикуемые сводки в `paper/generated/`.
