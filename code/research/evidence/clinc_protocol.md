# Продолжение исследования: независимый датасет и критерий настройки

Версия1,12ноября2026. План зафиксирован до обучения новых экспертов и просмотра результатов CLINC150. Это локальное продолжение исследования; существующие статьи, слайды, код, результаты и GitHub не изменяются.

## Вопросы

1. Воспроизводится ли обнаруженная на BANKING77 неодинаковая чувствительность gain-методов и weak-error к harm-rich отбору на новом датасете?
2. Сохраняется ли она, если регуляризацию выбирать по accuracy каскада при квоте вместо MSE прогноза прироста? Одна и та же сетка обученных кандидатов оценивается двумя критериями, без дополнительных ресурсов для одного из них.
3. Какие границы следуют из теоретического условия изменения top-k? Алгебраические проверки выполняются отдельно от реального эксперимента и не выдаются за новую в литературе теорему.

## Данные и эксперты

- CLINC150, официальный `clinc/oos-eval/data/data_full.json`, revision фиксируется до скачивания. Используется только in-scope классификация150классов; OOS не смешивается с новой задачей отказа.
- Из официального train после заранее определённой дедупликации70%каждого класса идут в expert-pool, остаток — router-fit-pool. Из expert-pool85%настройки выполняют внутреннее обучение,15%—выбор C; полные эксперты затем refit на expert-pool.
- В train одинаковые нормализованные тексты с одной меткой объединяются; конфликты меток удаляются из train целиком. Dev очищается от повторов/конфликтов и пересечений с train. Нормализация:NFKC,casefold,свёртка пробелов. Official test сохраняется; дополнительный clean-test исключает текстовые пересечения с исходными train/dev, повторы test и точные совпадения с прежним BANKING77. Test-метки не влияют на обучение/выбор.
- Четыре эксперта: TF–IDF+LR(full), TF–IDF+LR(3примера/класс), TF–IDF+LR(10примеров/класс), frozen MiniLM+LR. TF–IDF low-label использует словарь полного expert-pool, то есть различается число gold-меток, а не доступ к неразмеченным текстам. Low-label C=16; полные C выбираются внутренне из прежних сеток. Эксперты после этого фиксируются.
- Все6направлений:TF3→TF10,TF3→TFfull,TF3→MiniLM,TF10→TFfull,TF10→MiniLM,TFfull→MiniLM. Направления заданы поддержкой меток/семейством, не доказанной стоимостью. Квота трактуется как число вызовов, не экономия денег.
- MiniLM: прежний локальный pretrained snapshot `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`; новый supervised head обучается исключительно на CLINC. Старые BANKING77 головы/веса не используются.

## Роутеры и сетка

- Весь набор8:weak_error,direct,marginal,events,ternary,joint,hurdle,soft_gain;confidenceконтроль.
- Те же8агрегированных признаков дешёвого эксперта, без признаков/ответа второго. Расширение признаков оставлено для отдельного протокола.
- Fit200/1000 извлечений с возвращением;20router-subsetseeds. Составы natural_raw,harm8_raw,harm8_ipw. Raw/IPW используют одинаковые строки и scaler. Условная голова hurdle использует известную условную нормировку весов.
- Сетка λ0.001/0.01/0.1/1; обученные кандидаты общие для обоих критериев. MSE выбирает одну λ; accuracy выбирает λ для каждой квоты10/20/40% отдельно. При точном равенстве выбирается более сильная регуляризация. Взвешенный train всегда оценивается на естественном dev.
- Official dev перемешивается общим seed: первые n/2 строк — tuning, позиции500–999 — selector. Эти части не пересекаются. На selector выбираются8методов+confidence отдельно для состава/критерия/квоты, порядок ties прежний. Отложенная часть dev используется для preflight; до начала основной сетки результаты test не просматриваются.
- Итого240условий(pair×seed×size),5760метод×состав fit-grid,23040candidatefits. Для двух критериев сохраняются выбранные индексы кандидатов и scores; подсчёт selected policies не равен числу уникальных обученных моделей.

## Метрики

Accuracy каскада при точной квоте, gainMSE, rescueprecision/recall/F1,harmrate/recall,профильR/H,выбраннаяλ,потеряselectorкtest-oracle. Ошибки fit/tune/select,количество уникальных строк и исходов также сохраняются. Confidence MSE не трактуется как калибровка gain.

## Основная статистическая семья

Область:n1000,квота20%,officialtest. Все6пар,20seeds,2000crossedpairedbootstrap,точныйresampledtop-k,одна centeredmax-tпоправка на **1698контрастов**:

- Gain−weak-error простые различия в3составах и2критериях:252.
- Gain−weak-error взаимодействие harm8raw относительноnatural,2критерия:84.
- Accuracy-tuning−MSE-tuning для8методов×3состава×6пар:144.
- Изменение gain−weak-error взаимодействия между критериями:42.
- IPW−raw для8методов×2критерия×6пар:96.
- Selector−weak-error и selector−confidence в3составах×2критерия×6пар:72.
- Все21попарное различие внутри7gain в3составах×2критерия×6пар:756.
- Gain-only взаимодействия harm8raw относительноnatural,2критерия:252.

Другие размеры/квоты и clean-test — описательные проверки. Модели/выбор по dev условно фиксированы внутри bootstrap; меняются запросы и seeds. Одна новая панель и зависимые пары не заменяют множество независимых датасетов. Поправка отличается от BANKING77-семьи, поэтому не сравнивать сам факт пересечения p=.05 как тест различия датасетов.

## Завершение и интерпретация

Все условия, все выбранные модели и метрики должны пройти replay-аудит. Сетка не расширяется ради значимости. Если результат не воспроизведётся либо критерий настройки его изменит, это ограничение существующего вывода, а не основание подбирать другой test. Теоретические условия не объявляются новым общим законом без отдельной проверки приоритета.
